# 导航栏与详情浮层宽度优化

## Context

远程真机（MatePad Air / ProMax、MateBook Pro、Mate XT 2、Mate XTs）实测反馈两个问题：

1. **平板 / 电脑三栏时左侧导航栏过宽**：宽度固定 190vp，导航项只有「图标 + 2 字标题」约 53vp，右侧约 117vp 全是空白，视觉上过于占位。
2. **三折叠横屏的个人信息浮层右侧空白过多**：详情以 `bindSheet`（`SheetType.CENTER`）展示，背板宽约窗口的 45%（1014vp 窗口约 460vp）或 70%（420vp 窗口约 294vp），且内容左对齐，右侧留白明显。用户要求宽度缩减 1/6 并居中。

目标：导航栏宽度缩小 50%（190 → 96vp）；详情浮层宽度缩为当前 5/6 并居中，交互保持不变。

## 现状代码（分支 1.0.1，1.0.1_FY 基本一致）

`Application/entry/src/main/ets/pages/Index.ets`

- `NavBar(collapsed)` 约 336–403 行：`.width(collapsed ? 68 : 190)`，内层 item 为图标 `Text` + 标题 `Text` + `layoutWeight(1)`，padding 左右各 `Spacing.S`(8)。
- `contentAvailWidth(hasSidebar)` 约 1033–1038 行：`const nav: number = hasSidebar ? (this.sidebarCollapsed() ? 68 : 190) : 0;`，是 `paneRowWidth / detailPaneWidth / treePaneWidth / catalogPaneWidth` 的输入，**必须同步修改**，否则三栏宽度会多算 94vp。
- `bindSheet` 约 1190–1196 行：`{ height: SheetSize.LARGE, dragBar: true, backgroundColor: Theme.paper, showClose: false, preferType: SheetType.CENTER }`。
- `detailSheet()` 约 1199–1227 行：`Column() { PersonDetailPanel({ uid, narrow: true, ... }) }.width('100%').height('100%')`。

SDK 事实（`common.d.ts` SheetOptions 约 11753 行起）：**只支持 height，无 width**。因此浮层宽度只能通过「背板透明 + 内容卡片自定宽度」实现，不能直接设 sheet 宽度。

`PersonDetailPanel` 根节点 `.width('100%').height('100%')`，内部 `Scroll` 使用 `layoutWeight(1)`，填满父容器即可正常滚动。

## 实施方案

### 1. 导航栏宽度 190 → 96（缩小 50%）

在 `Index.ets` 顶部（`const TAG` 附近）增加两个常量，替换两处硬编码：

```ts
const NAV_WIDTH_EXPANDED: number = 96;
const NAV_WIDTH_COLLAPSED: number = 68;
```

- `NavBar` 的 `.width(collapsed ? 68 : 190)` → `NAV_WIDTH_*`
- `contentAvailWidth` 中的 `68 / 190` → 同名常量

96vp 减去左右 padding 16、item 左 padding 12 后内容宽约 68vp，图标 17 + 间距 8 + 两字 28 = 53vp，可正常排下，无需改字号或改纯图标模式。

### 2. 详情浮层宽度缩 1/6 并居中

保留 `bindSheet` 交互（下滑关闭、点遮罩关闭、旋转自适应），仅调整视觉尺寸：

- `bindSheet` 选项改为：`dragBar: false`、`backgroundColor: Color.Transparent`、`radius: 0`、`shadow: { radius: 0 }`、`blurStyle: BlurStyle.NONE`，避免透明背板残留系统阴影/圆角/描边。
- `detailSheet()` 改为「外层居中 + 内层卡片」结构：
  - 外层 `Column`：`.width('100%').height('100%').alignItems(HorizontalAlign.Center)`
  - 内层卡片 `Column`：`.width('83.3%')`（相对 sheet 背板宽度缩 1/6）、`.height('100%')`、`Theme.card` 背景、`Radius.L` 圆角、`.clip(true)`
  - 卡片内包裹现有 `PersonDetailPanel({..., narrow: true})`，其余回调不变

宽度用百分比而非 `min(窗口宽×0.7, 480)` 的经验公式，可避免不同机型背板宽度差异导致的溢出或过度留白。

### 3. 两分支同步

`1.0.1` 与 `1.0.1_FY` 的 `Index.ets` 已分叉约 386 行（FY 多了 `treeDetailCollapsed`、`TreeContent`、Scroll 导航等），**不要 cherry-pick**，两个分支分别在各自文件的手工对应位置修改：

- 导航宽度：`NavBar` + `contentAvailWidth` 两处
- 浮层：`bindSheet` 选项 + `detailSheet()` 结构

FY 分支的 `treePaneWidth()` 依赖 `contentAvailWidth`，改常量后会自动跟随，无需额外调整。

2. **本机手机回归**（`hdc install -r` + `aa start`）：

   - 点击浮层外区域可关闭；旋转屏幕后宽度自适应
3. **真机确认**（本机无法覆盖，需用户复测）：
   - 平板 MatePad Air / ProMax、电脑 MateBook Pro 三栏：左侧导航明显变窄，内容区相应变宽，无元素溢出
   - 三折叠 Mate XTs / Mate XT 2 横屏：个人信息浮层缩窄并居中，右侧留白减少，无系统阴影/圆角残留

## 风险与回退

- 透明背板若仍残留系统阴影或描边，先检查 `radius/shadow/blurStyle` 是否生效；仍不行则改用 `CustomDialogController`（注意：`customStyle: true` 时禁止设置 width，需 `customStyle: false` 并通过 options 的 `width`/`alignment: DialogAlignment.Center` 控制，同时用 `@StorageProp('gpSelection')` 解决弹窗内切换人物不刷新的问题）。
- 导航栏缩至 96vp 后若个别语言/字号下标题换行，可将该分支改为纯图标模式（复用 `collapsed` 布局，68vp），需再做一轮真机确认。
