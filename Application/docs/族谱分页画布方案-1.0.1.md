# 族谱分页画布方案（1.0.1 版）

> 适用代码：`E:\HarmonyOS\miyuan_yunkaifa`（HEAD = `refs/heads/1.0.1`）
> 目标：欧式谱 / 苏式谱由「无边界画布」改为「220mm×320mm 分页画布」，预留装订位，跨页可衔接，并为将来导出印刷 PDF 留接口。本文只给方案，不涉及代码修改。

---

## 0. 结论先行

**分页不是「把一张大画布切成 N 块」，而是「把族人分成 N 页，每页独立布局」。**

- 每页只排本页的人：页内的每一条线，两端都在本页，**结构上不可能出现跨页悬空线**。
- 页与页之间不画线，用三类文字接续：**页眉（支系）、页根角标（承第 N 页）、页脚（见第 N 页）**。
- 这样每页都是一张「闭合」的谱图，既适合屏幕翻页看，也天然适合逐页印刷 / 导出 PDF。

实测对比（1200 人 / 11 世 / 590 个叶子，卡片 16×7mm，版心 185×270mm）：

| 做法 | 苏式页数 | 每条页边界平均悬空线 | 最差一条边界 | 欧式页数 | 平均悬空线 |
| --- | --- | --- | --- | --- | --- |
| A. 大画布按页面尺寸硬切 | 66 | **4.4 段** | 8 段 | 44 | **5.0 段** |
| C. 逐页重排（本方案） | 66 | **0 段** | 0 | 44 | **0 段** |

> 口径：按现有 `EuLayout` / `SuLayout` 的占位规则（叶子占位、父节点居中、世代列/行）模拟；页数按页面容量估算，实际由装箱结果决定。3000 人 / 12 世时 A 的悬空线为苏式 808 段、欧式 265 段，C 仍为 0。
>
> 还有一种中间做法 B「整房打包但不重排」：页数接近 A，悬空线会少一些，但**不会是 0**——切线落在树的第 d 层，就会有 d+1 条祖先母线被截断（切在五世，前面四世的母线都跨页），仍需逐条画端口。切得越浅越省线、但版面浪费越大，本质是在「断线数量」和「页数」之间做交换；逐页重排直接取消了这个交换。

**为什么不做「端口线」？**
一条页边界会同时切断 4~5 条母线（最差 8~9 条），若在切口画端口，每条边界要挂 8~10 个标签，而且母线的「主人」常常在上一页远处，标签指向会很含糊——用户看到的仍然是「一堆线头」。逐页重排把这个问题从「标注问题」变成「不存在的问题」。

### 1.2 缺口（不补这几项，分页尺寸无从谈起）

1. **没有「页」的概念**：全项目没有 mm / pt / 版心 / 装订口，`TreeCanvas` 只有 `canvasW/canvasH`。
2. **卡片几何写死**：
   - 欧式 `cardH = Math.max(44, rowHeight - 4)`（L252），最小 44；
   - 苏式 `cardH = dense ? 62 : 74`（L538），`rowGap = dense ? 14 : 24`（L536），`COL_GAP = 16`（L525）；
   - `spouseGap = 12`、`lineGap = 6`、`stackGap = 6/10`、`busStep = 14` 全是屏幕像素口径。
   - 直接拿 220mm 页面去套，会把 44/74 当成 44mm/74mm，卡片比整页还大。
3. **布局根固定从第 0 层开始**：`place(node, depth)` 的 `depth` 从 0 起（L291 / L592）。逐页重排时，页根是「第五世的支祖」，如果仍按 depth=0 摆，会掉到第一世的位置。**必须支持「起始世代」参数**。
4. **布局会遍历全部子孙**：`place()` 无条件递归 `node.children`。要只排一页，必须支持「允许集合 / 切线集合」，遇到不在本页的子节点就停。
5. **`LineSeg` 只有几何 + `red` 标记**（L15~L24），没有「属于谁、什么关系」。若走端口方案，无法生成可读标签——这也是推荐逐页重排的原因之一。
6. **PDF 是 A4 文字流**：`PAGE_W=595.28 / PAGE_H=841.89`（`PdfExportService.ets` L24~L25），`paginateEntries`（L492）只排条目文字，**没有任何世系图页**；要印谱图必须新增 220×320 的页面规格与绘制路径。

## 2. 页面规格：220mm×320mm 到底怎么算

### 2.1 成品与版心（关键：出血在成品外，不占版心）

| 项 | 数值 | 说明 |
| --- | --- | --- |
| 成品尺寸 | **220 × 320 mm** | 与纸质族谱一致 |
| 出血 | 3 mm（四周，成品外） | 仅整页底色/边框需要；媒体尺寸 226×326mm |
| 装订口 gutter | **20 mm** | 内容禁入；胶装/缝纫装都够 |
| 翻口 fold | **15 mm** | 手指翻页区 |
| 天头 head | **25 mm** | 放谱名、堂号、支系、世代范围 |
| 地脚 foot | **25 mm** | 放页码、「见第 N 页」 |
| **版心** | **185 × 270 mm** | = 220−20−15 × 320−25−25 |

单位换算：

| 单位 | 页面 | 版心 |
| --- | --- | --- |
| mm | 220 × 320 | 185 × 270 |
| vp（96dpi，1mm=3.7795） | 831.5 × 1209.4 | 699.2 × 1020.5 |
| pt（72dpi，1mm=2.8346） | 623.62 × 907.09 | 524.41 × 765.35 |
| px（300dpi，1mm=11.811） | 2598 × 3780 | 2185 × 3189 |

### 2.2 奇偶页镜像（双面印刷必须做）

- 奇数页（recto，正面）：装订口在左，版心 x 起点 20mm，终点 205mm。
- 偶数页（verso，背面）：装订口在右，版心 x 起点 15mm，终点 200mm。
- 实现上只改「页面内容的平移原点」，不改布局；`pageInnerX(pageNo)` 返回 20 或 15。
- 若做折 signatures（多页一折），可再加 creep 补偿：内页按纸张厚度整体外移，`shift = t * (signaturePages/2 - pageInSignature)`；胶装可忽略。

### 2.3 装订方向可配

| 配置 | 适用 | 版心计算 |
| --- | --- | --- |
| `left`（默认） | 现代横排、左翻 | 左 20、右 15 |
| `right` | 传统竖排右翻 | 左 15、右 20 |
| `top` | 顶装（翻拍/挂谱） | 上 20、下 15，左右各 10 |

## 3. 印刷版布局参数：先把「卡片几何」从屏幕口径里拆出来

### 3.1 为什么要拆

屏幕卡片是 112~136vp 宽、62~78vp 高，为的是手指点得中；印在 220mm 页面上，一张卡只能占 9~16mm。**同一套几何参数不可能同时服务屏幕和纸面**，必须引入 `LayoutProfile`。

### 3.2 `LayoutProfile` 字段

| 字段 | 屏幕现值 | 印刷建议 | 作用 |
| --- | --- | --- | --- |
| `cardW` | 104~136vp | 16~28mm | 主卡宽 |
| `cardH` | 62~74vp | 8~12mm | 主卡高 |
| `colGap` | 16/30 | 3~5mm | 世代列间距（欧式）/ 兄弟列间距（苏式） |
| `rowGap` | 14/24 | 4~7mm | 世代行距（苏式）/ 兄弟行距（欧式） |
| `siblingGap` | 7/11/18 | 2~4mm | 同层兄弟间距 |
| `spouseGap` | 12 | 2mm | 夫妻卡间距 |
| `lineGap` | 6 | 1.5mm | 连线离卡框的留白 |
| `busStep` | 14 | 3mm | 多房母线层距 |
| `fontName/fontDetail` | 11~14vp | 6.5~8pt | 姓名/副行字号 |
| `showSpouse` | true | **false（推荐）** | 印刷版把配偶写进卡片文字，省一列、彻底消除「夫妻跨页」 |

> 印刷版建议 `showSpouse=false`：`TreeMiniCard` 本来就接收 `spouseText`，卡片里已有「配 林氏」。关掉独立配偶卡后，欧式每世少占一列（约 22mm），苏式每片叶子少占一格，页数明显下降，且夫妻天然不会分页。

### 3.3 三档印刷参数与容量（版心 185×270mm）

| 档位 | 卡片 | 列距/行距 | 苏式每页列×行 | 欧式每页世代列×叶行 | 适用 |
| --- | --- | --- | --- | --- | --- |
| 紧凑 | 16×8mm | 19 / 11mm | 9 × 24 | 9 × 24 | 1000 人以上，页数优先 |
| 标准 | 22×10mm | 25 / 14mm | 7 × 19 | 7 × 19 | 多数宗谱（推荐） |
| 大字 | 28×12mm | 31 / 17mm | 5 × 15 | 5 × 15 | 老人阅读、支系少 |

容量公式：

```
每页槽位 = floor(版心宽 / 列距) × floor(版心高 / 行距)
苏式实际人数 ≈ 每页槽位 × 0.6~0.8（树形上窄下宽，上层天然留白）
欧式实际人数 ≈ 每页叶行 × 世代列 × 0.6（同理）
```

> 行距可按页面「拉伸」：世代数少时把 `rowGap` 调大，让谱面撑满 270mm，而不是缩在上半页。这是印刷版比屏幕版更需要的一个自适应。

## 4. 分页算法：房支装箱 + 逐页重排

### 4.1 三个基本定义

- **房（unit）**：一个节点连同它的全部子孙，构成一个不可再分的「房」。分页时优先整房不拆。
- **页根（page root）**：本页中「父亲不在本页」的节点。它是本页与上一页的接续点。
- **切线（cut edge）**：父子被分到两页的那条边。切线**不画**，改用页脚/角标文字接续。

### 4.2 装箱流程

```
plan(root):
  pages = []
  cur = newPage(1)
  queue = [root]

  while queue 非空:
    u = queue[0]
    if 试排(cur.roots + u) 放得下版心:
        把 u 整房放入 cur；queue.pop()
    else if cur 已有房:
        pages.push(cur); cur = newPage(pages.length+1)   // 整房移到下一页
    else:
        // 单房本身就超过一页：拆房
        if u 无子女:
            把 u 放入 cur（单卡也必须落页）；pages.push(cur)；cur = newPage(...)
        else:
            父卡 u 放入 cur
            i = 0
            while i < u.子女数 and 试排(cur + 第 i 子房) 放得下:
                放入第 i 子房；i++
            for 剩下的子房: queue.push(该子房，记录 from=u)
            pages.push(cur); cur = newPage(...)
```

要点：

1. **试排用真实布局**（`EuLayout/SuLayout` 对「本页 roots」跑一遍），比估算准；一页最多几十个根，开销可控。
2. **放不下就整房移走，不切房**：宁可留白，也不把一房切一半；只有「单房 > 一页」才拆。
3. **拆房只拆子女层**：父卡留在本页，子女按长幼依次进本页/下一页，保证「长幼有序」。
4. **页序 = 族谱阅读顺序**：苏式按房支从左到右、从上到下；欧式按宗支从上到下、世代从左到右。不要按网格强行 `row-major`，否则读者会在支系之间跳。

### 4.3 单房超页的处理（关键）

以苏式为例：四世祖李承业有 3 子，长子支下 200 人，一页放不下。

- 第 N 页：放李承业卡 + 长子房的一部分（能放多少放多少，按子房整房装）。
- 第 N 页脚：「李承业 三子：长子 李先觉 支下 200 人，见第 N+1 页」。
- 第 N+1 页首：页根 = 李先觉（角标「↑ 承第 N 页 · 李承业 长子」），在其下重排 200 人；若仍超页，继续按子房拆。

读者任何时候看到的都是：**本页最上面有一个明确写着「承第 N 页 某某之某子」的根卡**，不会出现「一条线从纸边伸出去，不知道连谁」。

### 4.4 页内重排

- 输入：本页 `roots`（页根数组）、`allowed`（本页允许出现的 uid 集合）、`baseGen`（本页最小世代）。
- 布局：调用现有 `compute`，但要加两个参数：
  - `allowed`：递归到 `children` 时，不在集合内的子节点直接跳过（就是切线）；
  - `baseGen`：`rowY/colX` 用「绝对世代 - baseGen」索引，保证页根不掉回第一世。
- 输出：本页 `EuCanvas/SuCanvas`，量出内容包围盒，平移到版心居中（苏式横向居中、欧式纵向居中；宽度不足时左对齐并留装订口）。
- 页内不画任何「到页外」的线：`allowed` 之外的人根本没进布局，`lines` 里也不会有它们的端点。

### 4.5 跨页衔接的三件套（不画线）

以第 12 页承接第 11 页为例：

1. **页眉（天头 25mm）**
   `陇西堂 · 李氏宗谱` ｜ `世系图 · 第五世—第八世` ｜ `承第 11 页：李承业（四世）三子 李先民 支下`
2. **页根角标（卡片右上角）**
   `↑ P11`，点按跳到第 11 页并高亮李承业；长按显示「李承业 → 李先民 父子」。
3. **页脚（地脚 25mm）**
   中间：`12 / 66`；右侧：`续见第 13 页：李先民 次子 李志诚 支下`。

配套再加一个 **世系图页码索引**（可放在卷末或目录后）：
`李先民 …… P12`、`李志诚 …… P13`。这样即使不翻页，也能从人名直接定位。

> 页码有两套：`planPage`（世系图册内 1..N）与 `pdfPage`（含封面/谱序的绝对页）。页内互引一律用 `planPage`，PDF 目录再用映射表转 `pdfPage`，避免加一页封面就全谱页码错位。

### 4.6 不变量校验（每次分页后跑一遍）

1. 每个 uid 恰好属于一页（配偶卡按 `showSpouse` 规则单独计）。
2. 每条 `LineSeg` 的两端盒子都在同一页（由 `allowed` 保证，仍要断言）。
3. 每条切线 `(p, c)` 满足 `page(p) < page(c)`，且 `c` 是本页的页根（或页根祖先链上的人）。
4. 每个页根都有 `fromPage/fromUid`，且 `fromPage < 本页`。
5. 所有页根都能在上一页找到被切记录；所有被切父节点都有页脚「见第 N 页」。
6. 页数 = 页脚总数；无空页、无重页。

任何一条不满足 → 回退重排（把最后装入的房移到下一页），不允许「带病出图」。

## 5. 数据结构与伪代码（ArkTS 口径，仅供评审）

```ts
// 页面规格
export interface PageSpec {
  trimW: number;        // 220 mm
  trimH: number;        // 320 mm
  gutter: number;       // 20 mm
  fold: number;         // 15 mm
  head: number;         // 25 mm
  foot: number;         // 25 mm
  bleed: number;        // 3 mm（成品外）
  binding: 'left' | 'right' | 'top';
}

// 印刷版布局参数
export interface LayoutProfile {
  cardW: number; cardH: number;
  colGap: number; rowGap: number; siblingGap: number;
  spouseGap: number; lineGap: number; busStep: number;
  showSpouse: boolean;
  nameFont: number; detailFont: number;
}

// 页根
export interface PageRootRef {
  uid: string;
  fromPage: number;     // 0 = 本支始祖，无承接
  fromUid: string;
  relation: string;     // 「三子」「长子」「继配之子」…
}

// 一页的分页计划
export interface PagePlan {
  index: number;              // 谱内页码 1..N
  genFrom: number; genTo: number;
  roots: PageRootRef[];
  uids: string[];             // 本页全部人物（校验/索引）
  cutChildren: Map<string, string[]>; // 父 -> 被切到后页的子
  recto: boolean;
}

// 一本书
export interface PrintBook {
  spec: PageSpec;
  profile: LayoutProfile;
  pages: PagePlan[];
  indexByUid: Map<string, number>; // uid -> 谱页码
}
```

分页服务骨架：

```ts
class PaginationService {
  static buildBook(roots: PersonNode[], spec: PageSpec, profile: LayoutProfile): PrintBook {
    const pages: PagePlan[] = [];
    const queue: Unit[] = roots.map(r => ({ node: r, from: null }));
    let cur = newPage(1, spec);
    while (queue.length > 0) { /* 4.2 的装箱流程 */ }
    if (cur.roots.length > 0) pages.push(cur);
    const book = { spec, profile, pages, indexByUid: index(pages) };
    validate(book);        // 4.6
    annotate(book);        // 两遍：回填「承第N页 / 见第N页」
    return book;
  }
}

// 页内布局
function layoutPage(page: PagePlan, allowed: Set<string>, baseGen: number,
                    profile: LayoutProfile): EuCanvas | SuCanvas {
  return style === 'EU'
    ? EuLayout.compute(page.roots.map(r => nodeOf(r.uid)), profile, allowed, baseGen)
    : SuLayout.compute(page.roots.map(r => nodeOf(r.uid)), profile, allowed, baseGen);
}
```

> 注意：`allowed` 是集合，`compute` 里遇到 `!allowed.has(child.uid)` 就 `continue`；线生成只遍历 `placed`，因此不会画出切线。这是「零悬空」的代码级保证。

## 6. 屏幕端改造（只加不改，连续视图保留）

1. **双模式**：`TreeCanvas` 加 `paged: boolean`（或 `TreeStyle.PRINT`）。连续视图保持现状（总览、查找、缩放）；分页视图新增 `PagedTreeView`。
2. **分页视图结构**：
   - 外层 `PageFrame`：220:320 比例，白底、装订线、页眉页脚；
   - 内层 `PageRenderer`：画本页 `boxes/lines`（复用 `TreeMiniCard`、`Row` 画线、`lineThicknessOf`）；不用 `EuTree/SuTree` 的视口逻辑，因为一页内容很少。
3. **手势**：
   - 左右（或上下）滑动翻页，带 1/3 页跟手；
   - 双指捏合在页内缩放（1×~3×），平移夹在页框内；
   - 双击页根角标 / 页脚「见第 N 页」→ 跳页 + 高亮。
4. **导航条**：`12 / 66`、上一页/下一页、支系索引（下拉或索引页）、回到连续视图。
5. **查找**：`runSearch` 结果改为「跳页 + 高亮」；命中人不在当前页时，先翻到 `indexByUid` 再 `focus`。
6. **性能**：`PagePlan` 一次算好常驻；页布局 LRU 缓存 3~5 页（翻页即命中相邻页）；分页计算放 `TaskPool` 或分片 `yield`，避免大谱主线程卡顿。

## 7. 与 PDF 的接口（本次不修，只留契约）

- 页面尺寸：`623.62 × 907.09 pt`（220×320mm）；版心 `524.41 × 765.35 pt`。
- 逐页消费 `PrintBook.pages`：
  1. 页眉/页脚 → `addTextObject`（矢量文字，可搜索）；
  2. 卡片框 + 姓名 → 矩形 + 文本对象；
  3. 连线 → 若 `pdfService` 支持路径，直接画线段；不支持则把整页以 300dpi 渲染成位图 `addImageObject`，页眉页脚仍走矢量文字。
- 两遍排版：第一遍得到 `uid -> planPage`，第二遍回填「承第 N 页 / 见第 N 页 / 索引」。
- 分卷：沿用 `PdfExportService.planVolumes`（按世代聚合），每个 `PdfVolume` 持有一组 `PagePlan`；卷内页码从 1 起，跨卷标注「另卷」。
- 目录：`世系图目录`（支系 → 页码）+ `人名索引`（姓名 → 页码），放卷末。

## 8. 实施顺序（建议按里程碑验收）

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |

## 9. 风险与边界

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| 单房超大 | 一房 500 人，拆到十几页 | 只拆子房；页根标「承第 N 页」；页眉标世代范围 |
| 多妻/继室 | 苏式多妻竖排会抬高整行，挤压别房 | 印刷版 `showSpouse=false`，配偶进卡片文字；或按「妻妾数」预留行高 |
| 过继/双父 | 人物图是树，不是网；过继子只出现一次 | 以承嗣父为准入树；条目页写「本生父」并给页码 |
| 环形关系 | 现有 `visiting` 保护 | 分页布局沿用，跳过成环边 |
| 页码漂移 | 改一个字，后面页码全变 | `bookVersion` 标记；已打印页标记「待重排」；可选手工锁页 |
| 性能 | 大谱逐页试排 | 页布局 O(页内人数)，总量 O(n)；试排失败一次即换页，最坏 O(页数×房数) |
| 分卷边界 | 页跨卷 | 先分卷再分页，卷内独立编号 |
| 打印套色 | 朱砂红线印刷 | 线色改为 CMYK 可印的暗红 `#8C2F39`，避免 RGB 荧光红 |

## 10. 需要你拍板的 5 个参数

1. **装订方向**：左装订（默认）/ 右装订（传统竖排）/ 顶装？
2. **卡片档位**：紧凑 16×8 / 标准 22×10 / 大字 28×12？
3. **配偶呈现**：印刷版是否同意 `showSpouse=false`（配偶写进卡片文字）？
4. **单双面**：双面印刷要不要做奇偶页镜像（建议要）？
5. **页序习惯**：苏式按「房支」阅读（推荐），还是按「网格从左到右」？

这 5 项确定后，M1 的参数表和 M2 的页序规则就能一次定死，不用返工。
