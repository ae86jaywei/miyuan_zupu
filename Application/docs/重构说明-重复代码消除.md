## 一、重构原则

1. **行为等价优先**：只做结构性抽取/删除，不改变任何可观察行为与 UI 样式。
2. **低风险优先**：优先处理无状态、可逐行搬移的重复；对涉及 ArkUI 状态传递的高风险重复，明确记录并暂缓。
3. **不越界**：本次不处理超大函数、复杂度、魔法数字等其它异味。

## 三、逐项说明与行为等价性

### R1 + R6~R10：返回按钮组件化

**问题**：`ImportExport / Login / PersonEdit / Settings / SharedView` 以及 `PageNavBar` 各自复制了同一段返回按钮：

```ts
Text('‹')
  .fontSize(22).fontColor(Theme.ink).width(32).height(32)
  .textAlign(TextAlign.Center)
  .onClick((): void => { this.getUIContext().getRouter().back(); })
```

**重构**：新增 `BackButton` 组件，只保留「图标 + `onBack` 回调」；5 个页面与 PageNavBar 统一调用。

**等价性**：新组件逐字搬移原样式（字号 22、宽高 32、居中、颜色 `Theme.ink`），仅把点击逻辑委托给 `onBack`。页面侧回调仍为 `this.getUIContext().getRouter().back()`，点击行为不变。

> 说明：未把整行顶栏替换为 `PageNavBar`。原因是各页面右侧操作差异大（PersonEdit 有「删除 + 保存」按钮、SharedView 有「人数」、ImportExport 有 loading），且原高度 34 与 PageNavBar 的 44 不同，整体替换会改变布局；因此只抽取无差异的返回按钮，保证视觉与交互等价。

### R2 + R11 + R12：树画布公共逻辑抽取

**问题**：`EuTree` 与 `SuTree` 中以下实现逐行重复：

- `lineThickness()`：`1.5 / (zoom > 0 ? zoom : 1)`
- `isHorizontal(seg)`：`Math.abs(seg.y2 - seg.y1) <= 0.5`
- `root()`：遍历 `GenealogyService.getRoots()` 按 uid 匹配
- `viewKey()`：11 个字段拼接触发缓存
- `refresh()` 中内容可视矩形计算

**重构**：新增 `TreeCanvasShared.ets`，导出纯函数 `lineThicknessOf`、`isHorizontalSeg`、`findRootNode`、`treeViewKey`、`contentViewRect`；两个组件改为调用。

**等价性**：
- 函数体为逐行搬移，未改任何常量与比较符号。
- `viewKey` 拼接顺序与原实现完全一致。
- `contentViewRect(offsetX, offsetY, contentTop, ...)` 内部仍调用 `ViewportMath.contentRect(offsetX, offsetY + contentTop, ..., margin = viewWidth * 0.5)`，参数语义不变。
- 两个组件的 `@State`、渲染、`TreeCuller` 调用均未改动。

> 说明：`EuTree` / `SuTree` 的 `build()` 中约 90 行卡片/连线渲染高度相同，但**未**抽成共享组件。原因是 ArkUI 中把 `EuBox[]` / `SuBox[]` 作为 `@Prop` 跨组件传递会深拷贝其内含的 `PersonNode` 环状结构（项目内已有同类注释警告），且 `@Builder` 按值参数不随父状态刷新。强行抽取会改变刷新行为，故仅在纯逻辑层去重。

### R3：PageNavBar 复用 BackButton

**等价性**：`PageNavBar` 原返回箭头样式与 `BackButton` 完全一致，回调由 `this.onBack()` 提供，替换后无差异。

### R4：删除 SectionCard.ets

**证据**：全仓库检索 `CardHeader` / `SectionCard`，除自身定义外**零引用**；`TS.ets` 与其实质重复且被 GraveMap、ImportExport 正常使用。

**等价性**：删除未被任何代码引用的组件，不参与构建产物，无行为影响。

### R5：grave-update 重复三元抽取

**问题**：同一文件内 6 处形如：

```js
grave.lng === undefined ? (existing ? existing.lng : 0) : grave.lng
grave.graveName === undefined ? ((existing && existing.graveName) || '') : grave.graveName
```

**重构**：

```js
function pick(obj, existing, key, def) {
  if (obj[key] !== undefined) return obj[key];
  return existing ? existing[key] : def;
}
function pickText(obj, existing, key) {
  if (obj[key] !== undefined) return obj[key];
  return (existing && existing[key]) || '';
}
```

**等价性**：
- `pick` 与原三元完全等价（含 `existing[key]` 为 `undefined` 时仍返回 `undefined` 的细节）。
- `pickText` 保留原 `|| ''` 的“falsy 归空串”语义。
- 替换处：`lng`、`lat`、`altitude`、`graveName`、`facing`、`bearing`、`routeNote`、`photoRefs`。
- `visibility` / `precision` 使用 `S.str(params, ...)`，语义不同，保持原样未动。
