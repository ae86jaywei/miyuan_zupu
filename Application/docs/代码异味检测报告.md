## 三、详细发现

### 3.1 Critical（必须优先）

#### C-01 超大且高复杂度：`TreeBuilder.build`
- **位置**：`Application/entry/src/main/ets/service/TreeBuilder.ets:15-269`
- **指标**：255 行、圈复杂度约 62、5 层嵌套
- **说明**：一个静态方法内依次完成：节点表构建、父子/母子挂接、配偶双向补全、随母子女寄挂、分支高度与后代数计算等。任何一步修改都要通读 250 行，回归风险高。
- **建议**：拆为 `buildNodeMap()`、`linkParents()`、`linkSpouses()`、`attachStepChildren()`、`computeStats()` 等私有步骤方法，`build()` 只做编排。

#### C-02 上帝组件：`PersonEdit` 组件
- **位置**：`Application/entry/src/main/ets/pages/PersonEdit.ets:216-2372`（文件共 2,372 行）
- **指标**：组件约 2,157 行、约 66 个方法
- **说明**：该 struct 同时包含：表单字段渲染、下拉选择器、日期选择面板、地图选点、坐标解析、校验、保存/删除流程等。字段与 UI 状态高度耦合，修改任一区块都可能影响整体。
- **建议**：按职责拆出 `PersonBasicForm`、`PersonRelationForm`、`PersonBiographyForm`、`GraveLocationPicker`、`PersonEditController`（状态与保存逻辑），用 `@Prop/@Link` 或状态模型通信。

#### C-03 超大且高复杂度布局算法：`TreeLayout.ets` 两个 `compute`
- **位置**：
  - `EuLayout.compute`：`service/TreeLayout.ets:238-474`（237 行、6 参数、复杂度约 44）
  - `SuLayout.compute`：`service/TreeLayout.ets:508-784`（277 行、复杂度约 55）
- **说明**：两个方法各含局部类 `EuBox/SuBox`、`placed`/`visiting` 环检测、`place()` 递归、配偶槽位、兄弟间距等。两者结构高度同构，属于“复制后改常量”的实现。
- **建议**：抽取公共的“树遍历 + 占位 + 环检测”骨架，参数化卡片尺寸/配偶布局策略；将单方法拆为 `prepareMetrics()`、`placeSubtree()`、`buildEdges()`。

## 五、检测方法与局限

- **ArkTS**：`.ets` 无法被标准 TypeScript 解析器直接解析（`struct`/ArkUI DSL），故采用“去注释/字符串 + 括号匹配 + 结构模式”的静态分析器，并显式排除 `Column/Row/Stack/Text/ForEach/LazyForEach` 等内置组件调用，避免把声明式 UI 误判为函数。
- **JS**：使用 `acorn` AST 解析，统计函数、复杂度、参数、嵌套、类。
- **重复代码**：按归一化行序列做跨文件 8 行滑窗精确匹配 + 文件级 `difflib` 相似度；ArkUI 的样式属性序列重复为声明式写法固有，已在报告中按“结构性重复”优先排序。
- **局限**：静态复杂度为近似值；装饰器/闭包内的箭头函数可能被合并到外层方法统计；`build()` 的长度受 ArkUI 声明式风格影响，判断时已结合可拆分子组件的可行性。

> 本报告仅做检测与分析，未修改任何源码。
