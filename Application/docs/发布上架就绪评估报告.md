## 一、结论

**未达到发布上架标准。**

当前具备完整的功能工程结构与基础配置，但存在 **4 类 P0 阻塞项**，任一未解决都无法通过构建发布或应用市场审核：

1. **签名使用调试 profile，且证书文件缺失** → 无法产出可上架的 release 包。
2. **隐私政策仅有文字、无链接/无正文/无独立页面**，且可绕过同意直接本地使用 → 隐私合规不达标。
3. **权限不合规**：`READ_MEDIA` 未被使用却已声明；定位权限无运行时动态申请。
4. **release 未启用混淆**，签名口令以明文形式入库 → 安全基线不达标。

此外有 8 项 P1 风险项（AGC 密钥入库、依赖未锁定、无测试、日志未移除等）。

## 二、P0 阻塞项（必须修复）

### B1 签名：调试 profile + 证书缺失
- **位置**：`Application/build-profile.json5:3-17`
- **现状**：
  - `profile` 指向 `./zhengshu/miyuanDebug.p7b`（**Debug 调试证书**）；
  - `storeFile` 指向 `./zhengshu/miyuan.p12`、`certpath` 指向 `./zhengshu/miyuan.cer`；
  - 仓库中 `Application/zhengshu/` **不存在**（已被 `.gitignore` 忽略）。
- **上架要求**：必须使用 AGC 申请的**发布证书（release p12 + release p7b）**，且构建机可安全获取。
- **影响**：release 构建无法完成；即使完成也无法通过应用市场签名校验。
- **修复建议**：
  1. 在 AGC 生成发布证书与发布 profile，替换 `miyuanDebug.p7b`；
  2. 证书文件不入库，构建机通过 CI Secret/密钥库注入；
  3. 为 release 单独配置 `signingConfig`，避免误用 debug。

### B2 隐私政策不完整
- **位置**：`pages/Login.ets:158-170`
- **现状**：勾选文案为“《用户协议》”“《隐私政策》”，但两者均为**纯 Text，无点击事件、无页面、无外部链接**；仓库内无隐私政策/用户协议正文。
- **上架要求**：应用市场要求提供**可访问的隐私政策**（AGC 后台配置 URL 或应用内页面），并在首次使用时取得用户明示同意。
- **附加问题**：登录页提供“暂不登录，先本地使用”，可**绕过协议勾选**进入应用；首次启动无独立隐私弹窗。
- **修复建议**：
  1. 编写隐私政策与用户协议正文（覆盖：收集的姓名/电话/微信/住址/定位/相册，用途、存储、共享、删除方式）；
  2. 应用内提供可滚动阅读页面，或在 AGC 配置隐私政策 URL；
  3. 首次启动即弹出隐私政策并记录同意状态，未同意不得进入主功能。

### B3 权限不合规
- **位置**：`entry/src/main/module.json5:51-92`
- **问题 1：多余权限**
  - 声明了 `ohos.permission.READ_MEDIA`，但代码统一使用 `photoAccessHelper.PhotoViewPicker`（安全控件），**全仓无 `READ_MEDIA` 使用**。
  - 违反最小权限原则，审核可能要求删除。
- **问题 2：定位权限未动态申请**
  - 声明了 `ohos.permission.LOCATION`、`APPROXIMATELY_LOCATION`；
  - 全仓**未找到 `requestPermissionsFromUser` / `abilityAccessCtrl` 调用**，而 `PersonEdit.ets:834` 直接调用 `geoLocationManager.getCurrentLocation`。
  - user_grant 权限未动态申请时，功能会因授权失败而不可用，且不符合审核对“权限申请时机与说明”的要求。
- **修复建议**：
  1. 删除 `READ_MEDIA`（保留 PhotoViewPicker 即可）；
  2. 在首次使用定位前调用 `requestPermissionsFromUser(['ohos.permission.APPROXIMATELY_LOCATION'])`，按结果降级；
  3. 权限理由字符串补充“仅用于墓葬位置记录”。

### B4 安全基线：release 未混淆 + 口令明文
- **位置**：`entry/build-profile.json5:6-16`、`Application/build-profile.json5:9/11`
- **现状**：
  - `release` 的 `obfuscation.enable = false`，`obfuscation-rules.txt` 定义的规则未生效；
  - `storePassword` / `keyPassword` 以明文（DevEco 密文串）写入入库的 `build-profile.json5`；
  - release 未配置日志移除规则。
- **上架要求**：非强制混淆，但应用市场安全扫描与等保要求建议开启；签名口令不应入库。
- **修复建议**：
  1. `enable` 改为 `true`，启用现有混淆规则；
  2. 增加 `-remove-log` 或发布版日志裁剪；
  3. 口令改为 CI 注入/local.properties，仓库只保留占位符。

## 三、P1 风险项（建议修复）

| 编号 | 项 | 现状 | 风险/建议 |
|---|---|---|---|
| R1 | AGC 密钥入库 | `AppScope/resources/rawfile/agconnect-services.json` 被 Git 跟踪，含 `client_secret`（2 处） | 客户端密钥泄露；建议改用 AGC 安全配置，限制包名/签名，必要时轮换 |
| R2 | 依赖未锁定 | 无 `oh-package-lock.json5`；`@hw-agconnect/auth` 为 `^1.1.0`；云函数依赖多用 `^` | 构建不可复现、供应链风险；锁定版本并提交 lock |
| R3 | 无自动化测试 | 无 `ohosTest` / `test` 目录 | 上架前回归无保障；至少补关键路径 UI/单元测试 |
| R4 | 日志未清理 | 未见 `-remove-log`，`console.error`/`hilog` 较多 | 发布版可能输出内部信息；建议发布构建移除调试日志 |
| R5 | 云数据库权限 | 之前已收紧 `World` 匿名权限，但需 AGC 重新导入生效 | 未重新导入则线上仍匿名可读 |
| R6 | 隐私字段未加密标记 | `objecttype/*.json` 中 phone/wechat/residence 多为 `isNeedEncrypt:false`、`isSensitive:false` | 建议将敏感字段标记加密/脱敏，并在隐私政策声明 |
| R7 | 云函数构建钩子 | 各 `package.json` 的 `preinstall` 执行 `../_shared/install-into-function.js` | 安装期代码执行面；建议改为受控构建步骤 |
| R8 | 设备形态适配 | `deviceTypes` 含 `2in1`，但未见 PC 端专项适配与测试 | 若未充分适配，建议先只上 phone/tablet，避免审核问题 |

## 五、上架前行动清单（按优先级）

1. **替换为发布签名**，配置 release signingConfig，证书走 CI 注入（B1）。
2. **补齐隐私政策/用户协议**：正文 + 应用内可读页面/URL + 首次启动同意（B2）。
3. **权限整改**：删除 `READ_MEDIA`，定位权限增加动态申请与降级（B3）。
4. **启用 release 混淆与日志移除**，签名口令移出仓库（B4）。
5. 收紧 AGC 配置、锁定依赖、补关键测试、重新导入 CloudDB 权限（R1–R5）。
6. 在 AGC 应用市场完成：隐私声明、权限说明、数据安全表单、内容合规与版本提审。
