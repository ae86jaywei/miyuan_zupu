# 觅源 · 族谱分页画布改造方案（220mm×320mm 印刷规格）

> 目标：把欧式谱 / 苏式谱从「无边界画布」改为「分页画布」，页面尺寸与 220mm×320mm 纸质族谱一致、预留装订位置，按页分配族人，跨页用端口标记衔接，杜绝悬空连线。分页模型与页面规格同时为将来的 PDF 印刷导出铺路（本次不改 PDF 导出功能）。
>
> 原则：**分页是「视图切分」，不是「重新布局」**。布局只算一次，分页只决定「哪个盒子画在哪一页、跨页线如何衔接」。

---

## 一、现状与问题

| 现状 | 问题 |
| --- | --- |
| `TreeLayout.ets` 在无限逻辑坐标空间一次算出全部盒子（`boxes`）与线段（`lines`），欧式谱纵向堆叠（高可达 200 万 vp），苏式谱横向排布（宽可达极宽） | 画布随族人增多无限变大，平移查找困难 |
| `EuTree.ets` / `SuTree.ets` 用视口裁剪 + translate/zoom 渲染，无页面概念 | 打印 / 导出时没有「页」的边界依据 |
| 已有 `docs/族谱PDF导出方案.md`：世系图按世代硬切多页横向拼接 | 连线在页边界处被裸切，出现悬空线，不知连到谁 |

核心诉求拆解：

1. **分页**：220mm×320mm 为页面单位，族人按页分配。
2. **装订**：页面内预留装订位置（gutter），内容不侵入订口。
3. **衔接**：任何跨页关系线两端必须有端口标记（出端口 → 第 M 页 / 入端口 ← 第 N 页），**禁止裸线悬空**。
4. **为 PDF 铺路**：屏幕渲染与未来 PDF 导出共用同一「分页模型」，页面即渲染单元。

---

## 二、总体架构：布局 / 分页 / 渲染 三层解耦

```
┌─────────────────────────────┐
│ 布局层（现有，不动）           │
│ TreeLayout → EuCanvas/SuCanvas│  无限坐标空间，一次算完
│ boxes[]  lines[]  buckets[]   │  （已有分桶索引，直接复用）
└──────────────┬──────────────┘
               │ 布局结果（逻辑坐标）
┌──────────────▼──────────────┐
│ 分页层（新增 PaginationService）│  核心新增
│ 页面网格 → 单元打包 → 跨页端口   │  输入：布局结果 + 页面规格
│ 输出：PaginationResult        │  输出：页面数组 + 跨页衔接表
└──────────────┬──────────────┘
               │ 分页模型（页面 = 渲染单元）
┌──────────────▼──────────────┐
│ 渲染层（改造）                 │
│ 屏幕：分页视图（翻页/缩放/跳转） │
│ 未来 PDF：逐页 OffscreenCanvas │  两路共用同一页内容数据
└─────────────────────────────┘
```

关键收益：

- 布局层不知道分页的存在，分页参数（页面尺寸、装订方向）改动**不触发重算布局**，只重算切分。
- 屏幕渲染与 PDF 渲染读同一份 `FamilyPage`，**版式永远一致**，不会出现「屏幕看得到、导出断线」。
- 布局缓存（`EuLayout.computeCached`）与分桶索引全部保留。

## 三、页面规格（220mm×320mm 印刷规格）

### 3.1 尺寸换算（统一以 mm 为逻辑基准）

| 用途 | 换算 | 结果 |
| --- | --- | --- |
| 屏幕预览（96dpi） | 220/25.4×96 | 831.5 × 1209.4 vp |
| PDF 导出（300dpi，印刷） | 220/25.4×300 | 2598.4 × 3779.5 px |
| PDF 页面（Points） | 220/25.4×72 | 623.6 × 907.1 pt |
| 出血 3mm @300dpi | 3/25.4×300 | 35.4 px |

> 分页模型内部使用**逻辑 mm**（或固定 scale 的逻辑单位，如 1mm = 3.78vp），渲染时才按目标 DPI 换算，保证屏幕与印刷同源。

### 3.2 页面区域划分

```
┌──────────────────────────────┐
│◌ 出血区 3mm（四周，印刷裁切）  │
│ ┌──────────────────────────┐ │
│ │ 天头（页眉区）25mm         │ │
│ │ ┌──────────────────────┐ │ │
│ │ │                      │ │ │
│ │ │    版心（内容区）        │ │ │
│ │ │  装订侧不画任何内容      │ │ │
│ │ │                      │ │ │
│ │ └──────────────────────┘ │ │
│ │ 地脚（页码区）25mm         │ │
│ └──────────────────────────┘ │
│◌ 出血区                      │
└──────────────────────────────┘
```

| 区域 | 尺寸 | 说明 |
| --- | --- | --- |
| 成品页面 | 220×320mm | 印刷裁切后尺寸 |
| 出血 | 四周 3mm | 底色/图片铺满，裁切余量 |
| 装订口（gutter） | 装订侧 20mm | **内容禁入区**，分页切分线即内容区边界 |
| 翻口 | 非装订侧 15mm | 视觉留白 |
| 天头 / 地脚 | 各 25mm | 页眉（谱名·卷·世系标题）、页码 |

**装订方向可配置**：`left`（现代横排谱，默认）/ `right`（传统竖排、右装订谱）/ `top`（册页式）。装订方向决定：
- 内容区的内缩边；
- 翻页方向与页码递增方向；
- 对开预览（v2）时左右页 gutter 对称（左页靠右、右页靠左）。

### 3.3 分页矩形（内容区）定义

```ts
interface PageSpec {
  pageWmm: number;      // 220
  pageHmm: number;      // 320
  bleedMm: number;      // 3
  gutterMm: number;     // 装订侧 20
  foldMm: number;       // 翻口 15
  headerMm: number;     // 天头 25（含页眉）
  footerMm: number;     // 地脚 25（含页码）
  bindSide: 'left' | 'right' | 'top';
  scale: number;        // 逻辑单位/px 换算（屏幕 3.78，PDF 300dpi 11.81）
}
```

分页器的切分对象是**内容区矩形**：`contentW = 220 - bleed*2 - gutter - fold`、`contentH = 320 - bleed*2 - header - footer`（mm，含出血时各边减去对应留白）。

## 四、分页模型（核心数据结构，新增）

```ts
/** 分页结果：整部谱的页面集合 + 跨页衔接表 */
class PaginationResult {
  pages: FamilyPage[];          // 按页码顺序
  crossLinks: CrossPageLink[];  // 全部跨页衔接（用于校验与索引）
  spec: PageSpec;
  version: number;              // 布局/分页参数版本，用于缓存失效
}

/** 一个物理页面 */
class FamilyPage {
  pageNo: number;
  originX: number;              // 本页内容区左上角在布局坐标系的坐标
  originY: number;
  boxes: PageBox[];             // 本页卡片（含全局坐标与页内坐标）
  lines: PageSeg[];             // 本页线段（已裁剪到内容区，含端口线）
  ports: PortRef[];             // 本页的跨页端口标记
  header: PageHeader;           // 页眉：谱名/宗支/卷/世系范围/页码
}

/** 页内卡片：全局坐标 → 页内坐标一次算好，渲染层不再换算 */
interface PageBox {
  uid: string;
  gx: number; gy: number;       // 全局坐标（来自布局）
  x: number;  y: number;        // 页内坐标 = g - origin
  w: number;  h: number;
  isSpouse: boolean;            // 配偶卡（永远与主卡同页）
}

/** 页内线段（已裁到内容区边界） */
interface PageSeg {
  x1: number; y1: number; x2: number; y2: number;
  red: boolean;                 // 婚约红双线 / 世系金线
  portRef?: string;             // 若该段端点是端口，关联 PortRef
}

/** 跨页端口：悬空线端的「续接标记」 */
interface PortRef {
  uid: string;                  // 关系端点人物
  name: string;                 // 姓名（标签用）
  genLabel: string;             // 世次（第 N 世）
  relation: 'parent' | 'child' | 'marriage';
  fromPage: number;             // 线从哪页来
  toPage: number;               // 线到哪页去
  dir: 'out' | 'in';            // out=本页出线 / in=本页入线
  x: number; y: number;         // 端口在页内坐标
}

/** 跨页衔接总表：校验「每一条跨页线都有出、入两个端口」 */
interface CrossPageLink {
  uid: string;                  // 人物 uid（关系端点）
  fromPage: number; toPage: number;
  outPort: PortRef; inPort: PortRef;
}
```

**不变量（硬规则）**：`CrossPageLink` 的每一条记录，`outPort` 与 `inPort` 必须成对存在；分页完成后做一次全量校验，发现「单端端口」即视为分页失败（抛出并回退为整单元移动），**保证屏幕上永远不出现裸悬空线**。

## 五、分页算法（核心）

### 5.1 单元（Unit）定义——两种谱式唯一差异

分页以「单元」为最小不可切对象。单元内部的连线全部闭合在单元内，**页内无悬空线**；只有单元边界之间的主干线会跨页，数量 = O(子支数)，可管理、可标记。

| 谱式 | 单元定义 | 切分主方向 | 依据 |
| --- | --- | --- | --- |
| 欧式（横轴世系） | 一棵子树（某祖先 + 全部后代），含其配偶卡 | 纵向（y）按页高堆叠 | 欧式画布横向是世代列（宽有限）、纵向堆人（高无限），按 y 切页最自然 |
| 苏式（竖式吊线） | 一个「房支 × 世代行」组（某父在某世的所有子女），含配偶卡 | 横向（x）按页宽排布 | 苏式画布世代是行（高有限）、人横向排（宽无限），按 x 切页最自然 |

单元构建直接复用 `PersonNode` 树结构（parent/children 天然存在），配合布局输出的盒子坐标：

```
collectUnit(node) → { rootUid, top, bottom, left, right, height, width, kids: Unit[] }
  top    = min(node 盒子 y, 所有后代盒子 y)     // 用 boxes 坐标计算
  bottom = max(node 盒子 y + h, 所有后代盒子 y + h)
  left/right 同理（配偶卡按坐标并入所属主卡的单元范围）
```

### 5.2 贪心打包 + 整单元移动 + 大单元递归拆分

以欧式（按 y）为例：

```
units = 后序遍历收集的全部子树单元（按 top 排序）
pages = []
cur = 新页面（剩余高度 = 内容区高）

for unit in units:
  if unit.bottom - unit.top <= cur.remainingH:
    cur.add(unit)                       # 放得下：整单元入页，内部零断线
  else:
    if unit.height <= 内容区高:
      cur = 新页面; cur.add(unit)        # 单元比一页小但当前页装不下：
                                        # 整棵子树移到下一页（宁可留白，不切断内部）
    else:
      enqueue(unit.kids)                # 巨型分支（单支超过一页）：
                                        # 递归拆成子分支继续打包
```

苏式按 x 对称实现（`unit.right - unit.left` 对比内容区宽）。

### 5.3 切分优先级（语义保真）

单元打包保证的是「旁系分支之间切」。跨页只允许发生在以下关系上，且必须配端口：

| 关系 | 切断代价 | 策略 |
| --- | --- | --- |
| 父子（直系主干） | 高 | 尽量不断；必须断时（跨页不可避免）由端口标记衔接，端口带人名 + 世次 |
| 夫妻 | 高 | **永不切断**：配偶卡并入主卡单元，整体移动 |
| 兄弟（同父同母组内） | 中 | 组内尽量不切；组边界可切 |
| 堂/从兄弟、旁系分支 | 低 | 首选切分边界 |

> 夫妻卡在布局中已是主卡右侧/下方的附属盒子，分页时按「坐标邻近 + uid 关联」并入主卡单元，从机制上杜绝「夫在 1 页、妻在 2 页」。

### 5.4 线段切分与端口生成

布局输出的是 `LineSeg`（线段）而非「整条折线」，天然适合分页：

```
for seg in lines:
  计算 seg 与所有页面内容区矩形的交点（Liang–Barsky 裁剪）
  if seg 完整落在某一页内 → 归入该页 lines
  else:
    按交点切成多段，每段归入对应页
    每一处「穿出页边界」的端点 → 生成 PortRef
    同一人物 uid 的 out/in 端口配对 → CrossPageLink
```

关键点：**端口挂在「人物」上，不是挂在坐标上**。标签显示「▶ 第 3 页 · 二世 · 王XX」；点击端口即跳转对应页并高亮该人物卡片（复用现有 `highlightUid` 机制），彻底解决「这条线连到谁」。

## 六、跨页衔接的可视化（防断层核心）

端口标记设计（传统谱常用「⨁」圆环续接符，这里用带方向与页码的圆端）：

```
第 1 页（出端口）                    第 2 页（入端口）
┌─────────────────────┐            ┌─────────────────────┐
│  始祖 曾祖          │            │                     │
│    │                │            │   ⏴ 第1页 ◯── 高祖  │
│    └─── ◯⏵第2页     │            │        │            │
└─────────────────────┘            │        ├── 玄孙甲    │
  悬空端不是「断头线」，             │        └── 玄孙乙    │
  而是指向明确目的地的端口          └─────────────────────┘
```

规则：

1. **出端口**（本页线端）：圆端 + 短线 + 标签 `⏵ 第 M 页 · 世系 · 姓名`。
2. **入端口**（本页线端）：标签 `第 N 页 ⏴ · 世系 · 姓名` + 圆端 + 短线。
3. 端口永远画在内容区边界内侧，不侵入 gutter。
4. 点击任意端口 → 翻到目标页 + 高亮目标卡（`highlightUid` 已支持）。
5. 分页完成后全量校验 `crossLinks`：任一 `fromPage`/`toPage` 缺失对端 → 重新分页（整单元移动），**不允许带着断头线上屏**。

### 7.3 布局参数变化时的行为

族人增删改 → `roots` 引用变化 → 布局缓存失效 → 布局重算 → **分页重算**（页码可能漂移）：

- 分页结果带 `version`；渲染层发现版本变化后提示「族人已更新，已自动重新分页」，并尝试保持当前高亮人物所在页。
- v2 增强：手动「固定单元到指定页」（pin），分页器尊重手动安排，不再移动被固定的单元。

## 八、为 PDF 印刷导出铺路（本次不做，仅预留契约）

现有 `PdfExportService` 的「按世代硬切」改为**逐页消费分页模型**：

```
for page in paginationResult.pages:
  off = new OffscreenCanvas(2598, 3779)          // 300dpi，220×320mm
  drawPageBody(off.ctx, page, scale=300/96)      // 盒子 + 线段 + 端口标记 + 页眉页码
  off.getPixelMap() → packToFile(JPEG)           // 复用现有链路
  pdfService 组页（623.6 × 907.1 pt）             // 复用现有链路
```

- 屏幕与 PDF 共用 `FamilyPage` 与「页面内容绘制」逻辑，只是绘制目标不同（ArkUI 组件 vs OffscreenCanvas 2D），**印刷版与屏幕版逐页一一对应**，不再有两套版式漂移。
- 端口标记在印刷版中直接打印（圆环 + 「见第 M 页」），纸质谱的「衔接」靠页码互见，无需交互。
- 页面区域（出血/版心/gutter）在导出时按印刷规格展开：屏幕预览不画出血，导出时绘制 3mm 出血底色。

## 九、实施步骤（里程碑）

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| M1 | 分页模型 + `PaginationService`（先欧式、纵向打包） + 单页静态渲染 | 欧式谱按 220×320 内容区正确分页，页内无悬空线 |
| M2 | 苏式横向打包 + 线段裁剪 + 端口生成与校验 | 苏式跨页主线两端有配对端口；`crossLinks` 校验全过 |
| M3 | 交互：翻页、页码跳转、端口点击跳转高亮、整页/页宽/100% 缩放、分页/连续视图切换 | 端到端可用，万人级谱分页不卡（分页在 taskpool 或分批做） |
| M4（后续） | PDF 逐页对接（复用现有 pdfService 链路） | 印刷 PDF 与屏幕分页逐页一致 |

> 性能：分页是纯计算（无 UI 创建），万人级盒子 O(n) 遍历 + 线段裁剪，主线程可承受；若 > 2 万人再考虑 taskpool。渲染沿用现有「视口裁剪 + 分桶」只画当前页，单页盒子数远小于全量，反而比现在更快。

## 十、风险与边界

| 风险 | 应对 |
| --- | --- |
| 单支超过一页（巨型分支） | 递归拆分：沿该分支的旁系子分支切，端口标记承接主干线（5.2 大单元递归） |
| 页码随族人增删漂移 | 版本号 + 自动重分页提示；v2 提供手动固定 |
| 配偶卡跨页 | 单元定义强制并入主卡，机制上不可跨页（5.3） |
| 屏幕与印刷尺寸不一致 | 全链路以 mm 为逻辑基准，渲染时才换算（第三节） |
| 现有「连续视图」体验退化 | 保留为可切换模式，共用布局缓存 |
| 布局成环（数据异常） | 沿用现有 visiting 环保护；分页器遇到环时按已布局盒子坐标切分，不递归下钻 |
