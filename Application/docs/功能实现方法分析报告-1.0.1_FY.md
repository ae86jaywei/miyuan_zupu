### 1.2 双 Zone 架构

```
端侧 ArkTS
 ├─ RDB(genealogy.db)  ←—— 唯一真相源
 ├─ Outbox 队列         ←—— 离线写缓冲
 ├─ 协作 Zone(miyuanfamily)：端侧权限 []，全部读写经云函数
 │     └─ 23 个云函数（sync-pull 是唯一读通道）
 └─ 备份 Zone(miyuanzupu)：端侧可直读直写
       └─ CloudFamilyMember / CloudFamilyMedia（旧版整谱备份/恢复）
```

- **协作 Zone**：端侧对象权限一律 `[]`，写走 `member-direct-write` / `change-submit`，读只走 `sync-pull`，权限判定唯一来源是 `Membership` 表。
- **备份 Zone**：面向「整谱备份/恢复/换机」，由 `CloudSyncService` 直接调用 `cloudDatabase.zone('miyuanzupu')` 与 `cloudStorage.bucket()`。

## 三、世系树：构建 → 布局 → 裁剪 → 渲染

### 3.1 树构建：`TreeBuilder.build()`

文件：`service/TreeBuilder.ets:18`

1. 以 `uid.trim().toUpperCase()` 建 `Map<string, PersonNode>`；
2. 关联父/母：`fatherId` → `node.father`，`motherId` → `node.mother`，母亲不在父亲子节点时挂到母亲（单亲展示）；
3. 关联配偶：优先 `person.spouses[]`（`TreeBuilder.linkSpouse`），旧数据回退 `spouseId`；
4. **双向补全**：任一方登记即可互相识别；
5. **随母子女挂靠**：生父不在谱、生母为本谱男子配偶时，树结构上寄挂继父（不改 `fatherId`）；
6. **共子推断夫妻**：共同子女的不同性别成年人自动补配偶；
7. 子女排序：出生日期 → 性别（男前）→ uid，写入 `siblingIndex`；
8. `index(root)` 建 uid→节点索引；`depthOf()` 统计最大深度；`MAX_METRICS_DEPTH = 256` 防脏数据爆栈。

`model/PersonNode.ets` 持有 `father/mother/spouse/spouses/children/descendants/siblingIndex` 等派生字段。

### 3.2 欧式布局：`EuLayout.compute()`

文件：`service/TreeLayout.ets:354`

- 算法：**自底向上「叶子计数 + 纵向堆叠」**；
- 列坐标 `colX[]`：第 N 世固定第 N 列；若 `showSpouse`，每列右侧预留 `spouseGap + spouseW`；
- `place(node, depth)`：
  - 叶子节点 `y = cursorY`；
  - 父节点 `y = (首子中心 + 末子中心)/2 - cardH/2`；
  - 每放完一个节点，`cursorY = max(卡底, 配偶堆叠底) + siblingGap`；
- 兄弟间距自适应叶子数：`≤6 → 18`，`≤14 → 11`，否则 `7`；
- 配偶按「正庶先后」（`spouseOrder`）在主卡右侧纵向堆叠，婚约画**朱砂红双线**（`pushDoubleLine`，法向量偏移 `marriageGap`）；
- 子女按生母分组引出母线，组内兄弟横线相连，异母子女经父母相连；
- **分页集合 `allowed: Set<string>`**：集合外子女停止下钻、不画切线；
- **环检测 `visiting`**：父链成环时占位返回 `null`，不进入 `placed/boxes`；
- **深度上限 `MAX_TREE_DEPTH = 256`**：超限按叶子占位；
- 输出 `EuCanvas { boxes, lines, width, height, rootBox }`；`EuBox` 含 `node/x/y/w/h/centerY`，`LineSeg` 含稳定 `id`（不能拿裁剪后下标当 `ForEach` key）。

### 3.3 苏式布局：`SuLayout.compute()`

文件：`service/TreeLayout.ets:681`

- 算法同为「叶子计数 + 横向排布」，但方向为**竖式吊线图**：
  - `rowStep = cardH + rowGap`，同世 `y` 相同；
  - 横向游标 `cursorX`，父节点 `x = (首子中心 + 末子中心)/2 - cardW/2`；
  - 配偶横排在主卡右侧，`ownW(node)` = 主卡宽 + 可见配偶数 × `(spouseW + spouseGap)`；
  - 子树右边界取「子孙右缘」与「本卡连配偶右缘」较大者；
- 同样支持 `allowed` 分页集合、`visiting` 环保护、深度上限；
- 常量：`CARD_GAP = 34`、`COL_GAP = 34`、`START_X = 8`；
- 输出 `SuCanvas { boxes, lines, width, height, rootBox }`。

### 3.4 视口裁剪：`TreeCuller`

文件：`service/TreeCuller.ets`

- `WeakMap<数组, 索引>` 缓存「按 y 排序副本 + 最大高度」：
  - `euBoxCache` / `suBoxCache` / `lineCache`；
  - `euIndexOf` / `suIndexOf` / `lineIndexOf` 首次构建；
- 查询：**二分定位 y 下界 + 区间扫描 + 视口相交判断**，复杂度从 O(N) 降到 O(log N + K)；
- 对外：`euBoxes(boxes, view)`、`suBoxes()`、`lines()`、`warmupEu()`、`warmupSu()`（在布局阶段预热，避免首帧排序长任务）。

### 3.5 布局缓存：`TreeLayoutCache`

文件：`service/TreeLayoutCache.ets`

- 单例，`euMap/suMap` 各容量 8 条（`MAX_ENTRIES = 8`）；
- key = `rootKey|revision|cardWidth|rowHeight/dense|showSpouse|startY`；
- 命中后 `delete + set` 移到 Map 队尾实现 **LRU**，超限只淘汰最早一条（不整体 `clear`）；
- `invalidate()`：数据变化时 `revision+1` 并清空；
- 布局完成后立刻 `TreeCuller.warmupEu/Su`；
- 调用方 `EuTree`/`SuTree` 还做了一层组件级 `cachedCanvas/cachedCanvasKey`，拖拽/缩放不重复拼 key 查缓存。

### 3.6 视口数学：`TreeViewport`

文件：`service/TreeViewport.ets`

- 变换约定：`屏幕坐标 = 内容坐标 × zoom + offset`；
- `ViewportMath.contentRect(offsetX, offsetY, viewW, viewH, zoom, margin)`：反算内容可视矩形（含半屏缓冲）；
- `clampScreenOffset()`：内容大于视口时 `[viewW - contentW×zoom - pad, pad]`，小于视口时居中；
- `clampScreenOffsetFree()`：手势/缩放期间不强制居中，避免抬手把卡片从手指下拉走；
- `ViewRect.intersects()` 做矩形相交。

### 3.7 画布交互：`TreeCanvas`

文件：`view/TreeCanvas.ets`（1,384 行）

- **多宗支堆叠**：`rootUids[]` + `branchTops/branchH/branchW`，每支一个 `EuTree`/`SuTree` 子画布，`contentTop` 传入子画布；
- **手势**：`GestureGroup(GestureMode.Parallel, PanGesture({fingers:1,distance:8}), PinchGesture({fingers:2}))`
  - `PanGesture.onActionUpdate`：`offsetX = clampXFree(startX + event.offsetX)`；捏合期间单指让位（`pinching` 判断）；`panResume` 吃掉恢复首帧累计位移；
  - `PinchGesture.onActionStart`：`pinchCenterOf(event)` 取两指 `globalX/globalY` 中点减去画布 `globalPosition`；`lockAnchor()` 锁定手指下的内容点；
  - `PinchGesture.onActionUpdate`：`offsetX = cx - anchorContentX × zoom`、`offsetY = cy - branchTopAt(idx, zoom) - anchorContentY × zoom`，锚点内容点固定不动；
  - 缩放范围 `MIN_ZOOM / MAX_ZOOM`（0.05~1.5）；手势中不夹边界，抬手后再夹；
- **初始居中**：`centerOnRootIfReady()` 用布局缓存返回的 `rootBox` 直接居中始祖（不线性扫描数万 boxes），可视区尺寸变化超过 5% 时重新居中；
- **一键全览**：`resetView()` 按内容尺寸取合适 zoom 并居中；
- **搜索定位**：`runSearch(q)` 在树内匹配姓名/uid 并计算目标坐标，`zoomInto()` 放大到固定 zoom；`SearchPanel/SearchOverlay` 展示结果；
- **LOD 分级**：见 3.8；
- **宗支下拉**：`BranchDropdown()` 使用 `LazyForEach(this.branchSource, …)`，宗支多时只建可见行；
- **谱式切换记忆**：`TreeScrollMemory` 在多谱式切换时作废 `AppStorage` 滚动键，防止定位到空白；
- **性能打点**：`TreePerf.begin/end('cull_eu'|'layout_eu'|…)`，`TreePerf.shouldDegrade()` 对 >1s 主线程长任务打 hilog 告警。

## 五、印刷分页与 PDF 导出

### 5.1 纸张规格：`PrintLayout`

文件：`service/PrintLayout.ets`

- `PageSpec`：成品 **320×220mm 横版**，`gutter=20`、`fold=15`、`head=20`、`foot=20`、`bleed=3`、`safeInset=6`；
- `contentWidth() = trimW - gutter - fold - safeInset`；`contentHeight() = trimH - head - foot`；
- `innerX(recto)` / `innerY()`；单位换算 `mmToVp()`（96dpi）、`mmToPt()`（72dpi）、`mmToPx300()`（300dpi）；
- `LayoutProfile` 三档：`standard()`（22×10mm 卡、7pt 名）、`compact()`（16×8mm、6pt）、`large()`（28×12mm、9pt）；`metrics()` 转成 `LayoutMetrics` 供 `EuLayout/SuLayout` 使用；
- 屏幕分页与 PDF 共用这一份规格，避免两套尺寸漂移。

### 5.2 分页规划：`PaginationService`

文件：`service/PaginationService.ets`（866 行）

核心原则：**分页是「重排」不是「切片」**。

- `PagePlan`：`index/genFrom/genTo/rootUids/rootNodes/uids:Set/cuts:PageCut[]/footerText/recto`；
- `PrintBook`：`pages[]`、`indexByUid`、`pageOf(uid)`、`page(index)`；
- `book(rootUid, style, version, profileName, onProgress)`：按 `rootUid|style|version|profile|spec` 缓存整本；
- 装箱规则：
  1. 以「房」为单位（一个节点 + 全部子孙），整房装不下就移到下一页，宁留白不切房；
  2. 单房超一页才拆：父卡留本页，子女按长幼依次尝试，放不下的整支作为后页页根（`PageRootRef` 记录来源页/父辈）；
- `fill()`：
  - 先按 `sizeMap` 预估能否整支放入；
  - **深度优先**收集候选（广度优先会先铺满整代，页高/页宽立即耗尽）；
  - **指数回退批量试探**：先试 16 人，装不下减半重试到 1；不用二分（装下对前 k 人不单调），不逐个试（5 万人 × 页内人数会主线程超 6s）；
- `cutUncovered()` / `cutChildren()`：本页未覆盖子女统一记 `PageCut`，页脚「承第 N 页」接续，保证不出现跨页悬空线；
- `MAX_PAGE_DEPTH = 256`、`MAX_PAGES = 20000`、`MAX_ITER = 400000` 防环/防死循环；
- `TaskPool` 空任务作 `yield`，避免分页规划被系统判定 `THREAD_BLOCK_6S`；
- `euPage(index)` / `suPage(index)`：按页懒取 `EuCanvas/SuCanvas` 并缓存。

### 5.3 矢量 PDF：`PdfExportService`

文件：`service/PdfExportService.ets`（1,128 行）

> 页面规格：A4 竖版 `PAGE_W=595.28pt`、`PAGE_H=841.89pt`，页边距 `MARGIN_LR=56`、`MARGIN_TOP=64`、`MARGIN_BOTTOM=52`；正文为逐人编记的文本流（非 320×220mm 分页画布，分页画布见 5.4）。

流程 `exportPdf(context, people, book, options, onProgress)`：

1. 输出目录 `context.filesDir + '/pdf_export'`（`fileIo.accessSync/mkdirSync`）；
2. `new OffscreenCanvas(CANVAS_W, CANVAS_H).getContext('2d')` **仅用于 `measureText` 度量**；
3. 封面/谱序/正文/家训分页（`paginateLines`、`buildCover/buildPreface/buildBack`）；
4. **两遍排版**：
   - 第一遍用等宽页码占位，得到 `uid → 页码`（`PaginateResult.uidPage`）；
   - 第二遍回填真实页码，用 `padLine()` 补足第一遍行数，保证分页与互引一致；
5. `prepareCrossRefs()`：跨卷互引先排一遍版，生成 `uid → 「第2卷358页」`；
6. 逐页写入：
   - `new pdfService.PdfDocument()`、`doc.createDocument(PAGE_W, PAGE_H)`；
   - 删除自带空白页 `doc.deletePage(0,1)`；
   - `doc.insertBlankPage(index, w, h)` + `page.addTextObject(text, x, y, style)`，**矢量文字可选中/可搜索**；
7. **内存看门狗**：每 4 页（`MEMORY_CHECK_EVERY_PAGES`）通过 `hidebug.getPss()` 读进程 PSS（BigInt → `currentPssKb()`），软上限 `MEMORY_SOFT_LIMIT_KB = 900MB`（2026-11 由 1200MB 收紧），超限抛可捕获错误并提示分卷，避免 native OOM 无日志崩溃；每页 `yieldToUi()`；
8. `doc.saveDocument(outPath)`，`finally` 中 `doc.releaseDocument()`。
9. `planVolumes(people, maxPerVolume)`：按家庭单元（夫妻不拆卷）分卷，`FamilyUnit` 并查集构建。

### 5.4 栅格版 PDF：`PagedPdfExportService` + `PdfRasterJob`

文件：`service/PagedPdfExportService.ets`（582 行）、`service/PdfRasterJob.ets`、`service/PdfTileTask.ets`

- 目标：印刷级 300dpi，320×220mm → 约 3780×2598px；**2×2 分块**（`TILE_COLS/TILE_ROWS = 2`），单块约 1890×1299px，避开 4096px 纹理上限；

- 每页：

  - worker `@Concurrent renderTileJob` → `PdfRasterJob.renderTileImpl()` → `paintRasterTile()` 在 `OffscreenCanvas` 上画纸面/装订口/页框/连线/卡片框；
  - `doc.insertBlankPage()` + `page.addImageObject(tile.path, x, y, w, h)` 贴分块图；
  - `page.addTextObject()` 叠加页眉、页码、接续文案、姓名/世次/UID（文字层不进栅格图，保证清晰可搜索）；
- 单卷最大页数 `PAGED_MAX_PAGES_PER_VOLUME = 4`（2026-11 由 8 收紧：每卷 16 张 300dpi 图，降低 PDFKit 保存时的 native 内存峰值），超出自动拆卷；
- 分页版内存看门狗：每 2 页检查 PSS，软上限 `PAGED_MEMORY_SOFT_LIMIT_KB = 850MB`；栅格并发由一次 4 块改为按行 2 块；JPEG 质量 95→88；每卷结束 `yieldToUi()` 给 GC 回收窗口；
- 临时分块文件必须等 `saveDocument` 成功后再删（`addImageObject` 只登记路径，保存时才读盘）。

## 六、导入合并引擎

文件：`service/ImportPlanner.ets`（770 行）——**纯内存、可预览、可回滚**。

### 6.1 三段式流程

1. **身份匹配**（`IdentityMatcher`）
   - `normalizeName()` 去全角/半角空白；
   - `birthYear()` 正则提取四位年份；
   - `fingerprint(p, names)`：姓名、性别、生日、父母姓名、世代、字派、配偶姓名（排序拼接）；
   - `score(a, b)`：姓名不一致或性别相反直接 0 分；基础 40 分，性别 +10/+4、生日完全一致 +20/同年 +12/未知 +8、父亲姓名一致 +15/未知 +5、世代一致 +10/未知 +3、字派 +2、配偶 +3；
   - 阈值：`autoMergeScore=85` 自动合并、`reviewScore=60` 疑似待核对。
2. **全局 uid 重映射**（`ImportPlanner.plan()`）
   - 本机索引 `localMap/localSet/names`，按「姓名|性别」「姓名|性别|世代」分桶召回候选；
   - 同编号且 `IntegrityService.compare` 无 error → 直接合并（重导入快速路径）；
   - `UidAllocator` 一次性登记本机、已删除黑名单、悬空引用、本批已分配编号，`take(gender)` O(1) 分配；
   - 扫描候选每 500 人 `yield` 一次，避免主线程 >6s 被强杀；
   - 输出 `ImportPlan { matches, remaps, people, warnings, errors }` + `mergeCount/newCount/skipCount/reviewCount/summary`。
3. **关系图修复**（`service/RelationGraph.ets`）
   - 悬空引用清理、配偶双向补齐、按树深度回填世代（`fixGenerationByDepth` 默认关闭，避免篡改史料）；
   - `RepairReport` 统计修复项。

### 6.2 落库与结果

`GenealogyService.applyImportPlan(plan, onProgress)`：

- 事务式批量 upsert + `saveSpouses`，失败回滚；
- 落库后 `RelationGraph.repair()` + `checkIntegrity()`；
- `ImportResult { saved, integrityErrors, danglingCount, oneWaySpouseCount, generationMismatchCount }`，`summary()` 生成可读结果。

**策略**：`ImportOptions.conflictPolicy`（`auto/defer/merge/new`）、`localFieldFirst`、`fixGenerationByDepth`。

## 七、协作同步（端侧）

### 7.1 三种同步模式

`model/FamilyDomain.ets`：`SyncMode.LOCAL / CLOUD_PENDING / CLOUD_READY`。

- `LOCAL`：仅本机，不写 Outbox；
- `CLOUD_PENDING`：已创建云家族但未发布基线，所有写先入 Outbox，点「发布到云端」后统一上传；
- `CLOUD_READY`：在线直写或提交审核，失败自动入队。

### 7.2 离线 Outbox：`OutboxService`

文件：`service/OutboxService.ets`

表 `outbox`：

```sql
id INTEGER PRIMARY KEY AUTOINCREMENT,
family_id TEXT NOT NULL,
op TEXT, scope TEXT, target TEXT, target_name TEXT,
payload TEXT, base_rev INTEGER, created_at INTEGER,
state TEXT DEFAULT 'PENDING', error TEXT, retry_count INTEGER DEFAULT 0
-- 索引 idx_outbox_family(family_id, state)
```

- 状态机：`PENDING → DONE`，永久失败 `FAILED`（可重试失败保持 `PENDING` 仅累加 `retry_count`）；
- API：`ensureTable/enqueue/pending/pendingCount/lastError/markDone/markFailed/retryFailed/compact`；
- `compact()` 只保留最近 200 条 DONE，避免队列表无限增长。

### 7.3 写路径编排：`FamilyService`

文件：`service/FamilyService.ets`

`afterPersonSaved(op, uid, name, patchJson, baseRev)` 决策树：

```
LOCAL / 未接入 → 'local'
无编辑权限 → 'readonly'
离线 / 无 store / CLOUD_PENDING → enqueueChange() → 'queued'
谱主 → directWrite()  → member-direct-write → 'synced'
编辑者 → submitChange() → change-submit        → 'submitted'
在线写失败 → setOffline(true) + enqueueChange()
```

- `afterBookSaved(book)`：谱元信息同样走 book 作用域 Outbox / 直写；
- `directWrite()` 调 `member-direct-write`，`submitChange()` 调 `change-submit`；
- `enqueueChange()` 写 Outbox 并更新 `gpPendingCount` / 同步状态文案；
- `listMembers/updateMember/rotateInvite/listPendingChanges/reviewChange/requestAccess/reviewAccess/listPendingAccess` 均封装对应云函数；
- `bindLocalBook/applyBookFamilyState/createLocalBookForFamily/deleteCloudFamily` 管理本地族谱与 `familyId` 绑定。

### 7.4 同步编排：`FamilySyncService`

文件：`service/FamilySyncService.ets`

`syncCurrent(reason, onProgress)`（`:55`）：

1. 前置校验：数据就绪、`familyId` 非空、已登录、云服务就绪、无并发（`gpCloudBusy`）；
2. `flushOutbox()`：
   - 逐条读 `OutboxService.pending()`；
   - `baseRev = item.baseRev > 0 ? item.baseRev : book.cloudRev`；
   - `scope === 'book'` 或谱主 → `member-direct-write`；否则 → `change-submit`；
   - 成功 `markDone`；失败按错误文案判定是否永久（`Conflict/已被他人修改/无权/只被授权/成环/已存在`）→ `markFailed(permanent)`，统计 `rejectedOutbox/conflicts/warnings`；
   - 结束后 `compact()`；
3. `pullAndReplay()`：
   - `sync-pull({ familyId, sinceRev, limit: PAGE_SIZE, offset })` 循环（`guard < 20`）；
   - 全量基线（`sinceRev=0`）分页拉取，`headRev` 作为后续增量起点；
   - 增量按 `ChangeLog.rev` 拉取，服务端按 `targetMemberId` 去重返回最新快照；
   - `replayMember()`：
     - 墓碑 → `applyRemoteChange(uid, null, rev, true)`（软删 + 断链 + 封存编号）；
     - 云端编号曾属于另一已删族人 / 同编号本机云端身份冲突 → `integrityBlocked++`，暂缓合入；
     - 正常 → `applyRemoteChange(uid, person, rev, false)`；
   - `GraveService.cacheRows(graves)` 缓存祖墓；`replayBook(bookRaw)` 回放谱元；

### 8.4 同步闭环

```
写：端侧 Outbox / 在线直写
    ├─ OWNER  → member-direct-write → rev.allocate + FamilyMember + ChangeLog(+FamilyPrivate/Grave)
    └─ EDITOR → change-submit        → ChangeRequest(PENDING)，不改 rev
审核：change-review → baseRev 过期标 SUPERSEDED；通过则 applyPatch + 新 rev + ChangeLog 一批 writeBatch
读： sync-pull(sinceRev) → ChangeLog(rev > sinceRev) 按 target 去重 → FamilyMember 最新快照
    → 端侧 applyRemoteChange → RDB → reload → GenealogyStore.notifyChanged
收： Family.rev 为唯一游标；端侧 cloudRev 为本地基线；冲突时停在上次 committedRev
```

### 8.5 隐私与合规设计

- 活人隐私 `phone/wechat/residence` **绝不进 `FamilyMember.payload`**，只写 `FamilyPrivate`，端侧权限 `[]`，仅 OWNER 经 `family-private-get` / `sync-pull` 读取（`sync-pull` 中 `isOwner` 才回填 `privates`）；
- 墓葬坐标迁到公开 `FamilyGraveLocation`；`visibility=FAMILY_ONLY` 时**物理删除**公开行，而不是靠端侧过滤；`precision=BLURRED` 坐标保留 4 位小数；
- 黄页只允许 `DIRECTORY_FIELDS` 白名单字段，出现 `person/uid/generation/phone/...` 直接拒绝；
- 媒体 `safeCloudPath()` 拒绝 `\`、绝对路径、`..`，且规范化后必须以 `familyId/` 开头；
- 变更摘要 `human.diffText` 生成可读审批流水；`family-delete` 需 `confirmTitle` 与谱名完全一致。

## 十一、已知限制与可改进点

1. **App Linking 未启用**：`EntryAbility.handleShareLink` 只解析 `want.uri`，当前无公网域名，分享实际走「文本 + 邀请码」；`SharedView` 为兼容通道。
2. **云侧查询上限**：`members.parentMapOf/personMapOf` 单次 `limit: 1000`，`sync-pull` 全量分页但增量 `ChangeLog` 单次最多 1000 条；超万人家族需关注分页/索引。
3. **`directory-search` 内存过滤**：先取 500 行再 `indexOf` 过滤，黄页规模大时需服务端前缀索引。
4. **Where 条件组合**：`db.query` 使用 `and()` 串接，OR 查询未封装。
5. **端侧直写 Zone**：备份 Zone 采用 `Authenticated: Read` + `Creator` 写，安全边界弱于协作 Zone（后者端侧 `[]`）。
6. **`FamilyMember.parentMapOf` 只取未删除成员**，与墓碑/历史关系链的边界需在数据治理中确认。
7. **PDF 分卷与互引**：跨卷互引依赖 `prepareCrossRefs` 两遍排版，人数极大时导出耗时仍较长；已有内存看门狗提示分卷。
8. **`sync-pull` 增量**：同一对象只返回最新快照，中间历史需查 `ChangeLog`（当前端侧未展示完整历史）。
