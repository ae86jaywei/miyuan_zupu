## 一、扫描结论与甄别

扫描共报 311 条（Critical 123 / High 16 / Medium 62 / Low 81 / Info 29）。经人工核验：

- **规则引擎的 SQL 注入告警（约 100 条）为误报**：`db.js`、`authz.js`、`validate.js` 等使用的是 CloudDB SDK 的条件式查询（`col.query().equalTo(field, value)`），字段名与操作符均来自代码常量，不存在字符串拼接 SQL。
- 真实可利用问题集中在：**身份伪造、路径穿越、越权写、角色提升、CloudDB 匿名权限、文档泄密**。
- 本次修复 **12 类**真实问题，另有 6 类需人工/平台侧处理（见第四节）。

## 二、已修复项

### C-01 身份伪造：本地无签名解析 JWT（Critical）
- **位置**：`CloudProgram/cloudfunctions/_shared/identity.js:78-98`
- **CWE**：CWE-347（签名校验缺失）、CWE-290（身份伪造）
- **根因**：当 `TOKEN_CLAIM_HEADER=jwt:sub` 时，代码直接 base64 解码 JWT payload 取 `sub` 作为 uid，**未校验签名**，攻击者可伪造任意用户。
- **修复**：删除本地解析分支，`verifyTokenCandidate` 不再产生可信 uid，统一交由 `verifyTokenRemote`（AGC 服务端）校验。
- **影响**：若线上曾依赖该开关，将不再生效；这是预期行为。

### C-02 身份伪造：网关身份探测范围过宽（High）
- **位置**：`identity.js:57-75`（`fromGateway`）
- **CWE**：CWE-290
- **根因**：未配置 `IDENTITY_FIELD_PATH` 时，会从 `event` 顶层、`event.user`、`event.auth` 探测 `x-user-id/uid` 等键，而这些位置可被 HTTP 触发器的请求体参数合并污染。
- **修复**：未配置固定路径时**只从 `event.headers` 读取**，不再回退到请求体可污染的位置。

### H-01 路径穿越：云存储路径前缀校验可绕过（High）
- **位置**：`CloudProgram/cloudfunctions/media-record/index.js`
- **CWE**：CWE-22
- **根因**：仅判断 `cloudPath.indexOf(familyId + '/') === 0`，`familyId/../otherFamily/x` 可绕过，把他人文件挂到自己谱下。
- **修复**：新增 `safeCloudPath()`，拒绝反斜杠、绝对路径与 `..` 段；规范化后仍必须匹配前缀，并校验 `familyId` 不含 `/`。

### H-02 越权写：客户端可控 mediaId 覆盖记录（High）
- **位置**：`media-record/index.js:23`
- **CWE**：CWE-639
- **根因**：`mediaId` 取自客户端，可指定已存在主键覆盖他人媒体记录。
- **修复**：媒体主键一律由服务端 `S.uuid()` 生成，忽略客户端传入值。

### H-03 权限提升：审批可授予 OWNER（High）
- **位置**：`CloudProgram/cloudfunctions/access-review/index.js:65-75`
- **CWE**：CWE-269
- **根因**：`grantedRole` 直接取自请求参数，可传 `OWNER` 提拔任意成员。
- **修复**：白名单仅允许 `VIEWER` / `EDITOR`，非法值回退到默认角色。

### M-01 授权期限放大：可设永久/超长（Medium）
- **位置**：`access-review/index.js`
- **CWE**：CWE-613
- **修复**：非加入类授权不允许 `expireAt=0`（永久）；期限统一上限 3650 天。

### M-02 撤销绕过：被移出成员可凭邀请码复入（Medium）
- **位置**：`CloudProgram/cloudfunctions/family-join/index.js:24-29`
- **CWE**：CWE-863
- **修复**：`Membership.status === REVOKED` 时直接拒绝加入，需谱主显式恢复。

### M-03 越权分支：加入时可自选 branchRootUid（Medium）
- **位置**：`family-join/index.js:35`
- **CWE**：CWE-639
- **修复**：加入时 `branchRootUid` 固定为空（全谱），分支授权由谱主单独分配。

### M-04 信息泄露：内部异常原文回传客户端（Medium）
- **位置**：`CloudProgram/cloudfunctions/_shared/index.js:172-182`
- **CWE**：CWE-209
- **修复**：仅 `BizError` 回传业务文案；其它异常统一返回“服务暂时不可用”，详细堆栈只写服务端日志。

### C-03 CloudDB 匿名权限（Critical/High）
- **位置**：`CloudProgram/clouddb/objecttype/*.json`（14 个对象）
- **CWE**：CWE-284、CWE-862、CWE-306
- **根因**：所有对象 `World` 角色均有 `Read` 权限，匿名即可读取家庭隐私、成员、邀请码、墓葬坐标等。
- **修复**：**全部对象的 `World.rights` 置空**；`Post` 为无业务引用的模板对象，`Authenticated/Creator` 的 `Upsert/Delete` 也一并移除，仅保留 `Administrator`。
- **保留项**：已登录用户的 `Authenticated Read` 保留，因为端侧 `GraveService` 等存在 CloudDB 直读，贸然移除会破坏功能。

### C-04 文档泄密：签名口令与绝对路径（Critical）
- **位置**：`Application/docs/GitCode推送指南.md`
- **CWE**：CWE-798、CWE-312
- **修复**：`storePassword` / `keyPassword` 脱敏为 `<REDACTED>`，`storeFile` 改为相对路径，本机绝对路径改为 `<项目根目录>`。

## 四、需人工/平台侧处理（未直接改代码）

| 项 | 位置 | 原因与建议 |
|---|---|---|
| `FamilyPrivate` 等表的 `Authenticated Read` 水平越权 | `CloudDB` 权限 | 端侧存在 CloudDB 直读；行级（familyId/属主）权限需改用云函数或 ACL，不能靠对象级权限解决 |

| `function-config.json` 的 `authFlag: "true"` 字符串 | 各云函数 | 是否应改为布尔需以 AGC 网关实际规范为准，贸然修改可能影响鉴权 |
| `preinstall` 执行 `install-into-function.js` | 各 `package.json` | 属部署期复制 shared 的构建机制；建议改为受控构建脚本并锁定依赖 |
| `.gitignore` 忽略 lock 文件、签名私钥历史 | 仓库根/历史 | 依赖可复现性与历史私钥需用 `git filter-repo` + 换证书处理，属仓库治理 |
| `db.js` 等 SQL 注入告警 | `_shared/*.js` | 误报，无需修改 |

## 五、部署注意事项（重要）

1. **CloudDB 权限 JSON 修改后必须在 AGC 控制台重新导入/发布**才生效；仅改仓库文件不会改变云端权限。
2. **身份修复要求网关确实注入可信身份**：请确认线上已配置 `IDENTITY_FIELD_PATH`（指向网关注入的 header 路径），或配置 `AGC_VERIFY_URL` 用于服务端令牌校验；否则请求会因取不到可信身份而返回 401。
3. `media-record` 不再接受客户端 `mediaId`，客户端需以接口返回的 `mediaId` 为准。
4. 建议在 AGC 侧轮换已暴露的签名证书与 AGC 凭据（文档曾记录过口令与私钥路径）。
